# Capital ships (headless Blender)

One build script per faction capital ship, modelled from the Grok concept art in `ref/`.

```bash
bash tools/blender/setup.sh                  # once per session
python3 tools/blender/ships/lumen.py         # → out/lumen/{lumen.glb, lumen.blend, lumen_*.png}
python3 tools/blender/ships/sheet.py lumen   # → out/lumen/lumen_sheet.jpg (reference + 4 views)
```

`out/` is not committed; the scripts are the source.

## Rules every ship follows

- **Mirrored port to starboard.** Model the port side (+Y) and the centreline only. `common.build()` merges
  everything, cuts at y = 0 and mirrors, so anything modelled on the starboard side is discarded.
- **One mesh per material.** The same step merges parts by material: a ship costs one draw call per material.
- **Hard-surface lofts.** Hulls are lofts of chamfered-rectangle sections (`loft`, `box`, `cyl`), with no
  sculpting or subdivision.

## Detail scale (1 unit = 25 m)

Secondary details are drawn at one human scale on every ship, so the fleet reads as one world. The table lives
in `common.DETAIL`; `audit_scale.py` checks it. A capital ship is about 525–600 m, and the tug is 15 m.

| Class (name prefix) | Size | Real | Helper |
|---|---|---|---|
| `win_` window (lit) | 0.08 tall × 0.10 wide | 2 × 2.5 m | `window_row(name, start, end, glow, face)` |
| `port_` porthole (lit) | ⌀ 0.08 | 2 m | `porthole_row(…)` |
| `strip_` running light (lit) | 0.04 wide | 1 m | `light_strip(…)` |
| `band_` accent band (lit) | 0.08 wide | 2 m | `light_strip(…, wide=True)` |
| `door_` hatch / door | 0.12 × 0.16 | 3 × 4 m | `box` |
| `mast_` mast / antenna | 0.05 thick | 1.25 m | `mast(…)` |
| `strut_` scaffold member | 0.05 thick | 1.25 m | `scaffold(…)` |
| `gun_s_` / `gun_m_` / `gun_l_` barrel | ⌀ 0.06 / 0.12 / 0.22 | 1.5 / 3 / 5.5 m | `barrel(…, size=)` |
| `spire_` spire | base ≥ 0.15 | ≥ 4 m | `loft`/`cyl` |
| `stack_` smokestack | ⌀ 0.25–0.45 | 6–11 m | `cyl` |

- **Deck pitch** (`DECK`) is 0.16 (4 m). Stack window rows and terraces on it.
- **Exempt parts:** prefix `feat_` marks a one-off feature light (rose window, hangar mouth, signature outline), which is exempt from the table. Engine cores are exempt too.
- **The audit fails on:** any lit part with no class prefix, or any classed part more than 12% off its class.

```bash
python3 tools/blender/ships/<slug>.py tools/blender/ships/out/<slug> --no-render   # fast rebuild, writes parts.json
python3 tools/blender/ships/audit_scale.py <slug>                                    # 0 issues to pass
```

## Surface

All ships share three tiling 1024² textures, projected at world scale (`common.TILE` = 3 u), generated by
`detail_tex.py`:
- **Panel normal map:** seams, plate steps, vents and bolts.
- **Cavity map:** darkens the seams; multiplied into the vertex colour.
- **Roughness/metalness map** (glTF: G = roughness, B = metalness): every plate gets its own sheen, seams stay dull, and hatches, louvre lips and bolt heads catch the light.

## Geometry budget

| Use | Triangles | Materials (draw calls) | Textures |
|---|---|---|---|
| LOD0: close-up (capital ship screen, mission giver) | ≤ 6,000 | ≤ 4 | 1K on mobile, 2K on PC |
| LOD1: orbit view on the planet screen | ≈ 2,000 | ≤ 4 | shared with LOD0 |
| LOD2: fleet or far distance | ≈ 600 | 1–2 | none |

The per-ship cost is low next to a full frame. Mobile WebGL handles a few hundred thousand triangles, so the
budget is about keeping draw calls and texture memory down when several ships share a screen.

## Pipeline

1. `python3 tools/blender/ships/<slug>.py` — build, mirror, LODs, GLBs + renders in `out/<slug>/`.
2. `python3 tools/blender/ships/sheet.py <slug>` — reference beside the renders for review.
3. `python3 tools/blender/ships/publish.py <slug>` — copy the GLBs into `prototype/test-game/content/ships/` and
   update `ships.json`. Commit `content/ships/` with the script: the game loads content at runtime.
4. Review in the game's viewer: `prototype/test-game/tools/ships/viewer.html` (Pages: `/tools/ships/viewer.html`).

## In the game

`src/render3d/ships/engineFx.js`: `prepareShip(THREE, gltf.scene)` swaps in one shared body material and one
unlit glow material for the whole fleet (textures load once); `createEngineFx(THREE, root)` adds the exhaust from the
`engine_N` markers (radius + faction colour in extras) — 2 draw calls per ship, `setIntensity(0 … 2)` for
cold / idle / cruise / story burn, eased so it spools rather than snaps.

## Faction propulsion colours

`common.ENGINE_COLORS` — air pale blue-white, arcane magenta, artillery orange, collective deep blue, dark violet,
green chem green, lumen cyan, powder ember red, tech gold, water teal.
